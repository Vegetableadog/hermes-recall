# 功能路线图

以下为现有路线中聚合的 FR；状态反映当前资料，非实施承诺。

| FR | 目标 | 状态 | 主要依赖 |
|---|---|---|---|
| FR-001 Echo Ritual | 形成低摩擦的回响式自然语言记录、查询与反馈体验。 | Next（v1.1 候选） | v1.0 Core 稳定、真实使用反馈、语义输入/输出契约与测试基线。 |
| FR-002 Reminder Lifecycle | 区分 Reminder、Delivery、Attempt，建立可靠状态、幂等、错误与重试边界。 | Planned（v1.5；相关设计亦支撑 v1.4） | 现有 Scheduler/Feishu 兼容、Notification 数据契约、测试与迁移门禁。 |
| FR-003 Memory Evolution | 从单条记录走向结构化记忆、关联、时间演化与后续回顾。 | Next / Planned（v1.1 起） | 原始 content 保留、Schema 兼容、数据模型冻结、真实反馈。 |
| FR-004 Notification Ecosystem | 建立 Provider、Identity、Routing、统一配置与健康检查，为多平台准备。 | Planned（v1.4） | 现有 Feishu 不受影响、单渠道体验、数据兼容、Provider Contract 测试。 |
| FR-005 Productization | 通过 Experience Layer、Setup Wizard、Simple Mode 与 Personal Mode 降低使用门槛。 | Planned / Target | Core/通知/迁移稳定，用户隔离与配置模型明确。 |

长期路线还包含 v1.2 标签与关联记忆、v1.3 Weekly Review、v2.0 语义记忆和 v3.0 Personal AI Memory System；均未实现。SQLite 与 Vector Memory 是条件性存储演进，不由记录数量自动触发。
