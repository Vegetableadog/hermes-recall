# 架构概览

## 当前数据流

```text
用户输入
  ↓
Hermes 语义理解（分类、标签、时间解析）
  ↓
Recall Core / CLI
  ↓
JSON 存储（唯一事实来源）+ History
  ↓
Scheduler 到期扫描
  ↓
Hermes cron / Gateway
  ↓
Feishu 通知平台
```

Markdown View 从 JSON 单向生成，属于展示层，不参与反向写入。

## 当前职责边界

- Hermes Agent：理解自然语言、选择分类和标签、解析提醒时间、调用 CLI。
- Recall Core：记录 CRUD、状态与提醒字段、History、View 生成、迁移与升级。
- JSON / History：分别保存当前记录事实和审计历史。
- Scheduler：筛选已到期且仍待发送的提醒。
- cron / Gateway：按周期执行并将提醒文本投递给平台。
- Feishu：当前最终消息传输平台；webhook 为备用方式。

业务修改应通过 Core/CLI，不能直接编辑 JSON 或 Markdown View。

## 已确定的未来扩展方向（Target）

- **Reminder Lifecycle**：将提醒、投递和投递尝试分开建模，补足状态、幂等、失败与重试边界。
- **Memory Evolution**：在保留原始记录的前提下，逐步引入结构化记忆元数据、关系和时间线式演化。
- **Notification Provider**：以 Provider、Identity、Routing 等抽象扩展通知平台，Recall Core 不绑定单一平台。

这些是目标架构，不是当前实现。
