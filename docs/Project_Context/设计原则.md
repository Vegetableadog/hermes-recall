# 设计原则

> 状态：Current（项目设计原则，非基线内容复制）

1. **保留原始输入。** `content` 保存用户原始表达；分类、标签和后续结构化信息不得静默覆盖它。
2. **历史优先。** 创建、修改、完成、删除及提醒活动应留痕；不能为当前便利抹去过去的上下文。
3. **单一事实来源。** 当前 `recall.json` 是主数据；History 是审计历史；Markdown 是派生视图。
4. **提醒不等于完成。** Record 状态、Reminder 状态、平台投递和用户实际收到消息是不同层次的事实。
5. **明确时间才主动打扰。** 无明确提醒时间的信息只记录，不主动发送。
6. **数据可迁移。** Schema 演进必须保留兼容、迁移、备份与恢复路径；不要为了方便破坏未来 SQLite 映射或数据导出。
7. **避免过度工程化。** JSON 继续作为当前存储，直到真实性能、可靠性、并发或多实体需求触发复审。
8. **职责分离。** 语义理解、记录存储、调度和平台通知分别负责各自的边界。
9. **真实反馈优先。** 下一阶段由持续使用、提醒价值和用户困扰验证，而不是仅凭路线图推进。
10. **Core 稳定优先。** 先冻结契约、补足测试与数据安全，再扩展关联记忆、平台或产品化体验。
11. **隐私与可迁移性。** 用户数据、身份目标、凭据和运行日志不进入公开仓库或发布包。
