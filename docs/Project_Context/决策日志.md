# 重要设计决策

## 当前生效

### JSON 作为当前主存储

ADR-001（Accepted，2026-08-10）决定 V1.0 继续以 JSON 为主存储。理由是个人、低并发、本地使用场景下 JSON 易检查、备份和恢复；立即迁移 SQLite 会在数据契约和自动化基线尚未稳定时增加迁移与运维风险。该决定要求加强备份、Validator、测试与真实性能测量，并在明确触发条件出现时复审。

### 原始输入与历史优先

`content` 不被 AI 分类或标签覆盖；History 保存操作轨迹。此决定保障后续理解、迁移与追溯仍有原始依据。

### JSON 单向生成 Markdown

Markdown 是人类阅读视图，不作为主存储，也不与 JSON 双向维护，以避免两个事实来源。

### 不提前增加 `note` 字段

历史资料中的路线未把自由 `note` 字段列为 V1.0 已实现数据契约。当前选择是不为眼前记录便利而在未冻结演化模型前任意扩张字段；后续变化应遵循 Schema、兼容、迁移和测试约束。

### V1.0 不提前重构

V1.0 的策略是先稳定记录、提醒、数据与运维闭环，并通过真实使用收集证据；不因已存在 Notification、SQLite 或产品化路线就提前实现大型架构。

### 文档作为长期上下文

正式 Markdown 文档负责标记 Current / Target / Historical，归档原稿保留为设计来源，ADR 保存长期取舍。这样在不覆盖历史的前提下，维护者可以区分事实、目标和设想。

### Reminder、调度、投递分层

Reminder 不等于任务完成；Scheduler 不等于平台通知；平台接受也不等于用户实收。当前实现已有职责分离，完整 Delivery 生命周期仍待实现。

## 维护规则

Accepted ADR 不用改写历史理由来改变决定；若决定本身变化，应新建 ADR 并建立 Supersedes 链。Target 在实现、测试和验收前不能被表述为 Current。
