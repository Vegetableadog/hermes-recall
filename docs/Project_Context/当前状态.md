# 当前真实状态

## 基线

- 产品版本：Recall V1.0
- 当前状态依据：2026-08-10 的正式文档核验快照
- 主数据：JSON（`recall.json`）

## 已实现

- JSON 作为当前唯一事实来源；Markdown 仅为由 JSON 生成的阅读视图。
- 固定五分类：工作待办、生活日常、想法灵感、学习笔记、收藏。
- 记录的新增、查询、关键词搜索、更新、完成、归档/删除，以及优先级、标签和来源管理。
- 原始 `content` 保存、记录 ID、Schema 版本、操作 History。
- 旧 Markdown 数据迁移、历史 Schema upgrade、数据完整性校验。
- 有明确时间时创建 Reminder；统一 Scheduler 到期扫描。
- Hermes cron 周期调度；Gateway 投递链路；Feishu 通知，以及 webhook 备用方式。

## 当前限制

- Reminder 使用简化状态：`pending / sent / failed / cancelled`，尚未实现完整投递生命周期、Attempt、幂等和自动重试。
- Gateway 模式可能在 Recall 已标记 `sent` 后发生平台投递失败，二者存在确认窗口。
- 当前检索主要是内容与标签的关键词匹配，不是语义检索。
- Feishu 是当前主要通知能力；标准 Provider、Identity、Routing 和多渠道尚未正式实现。
- 源码内部存在 `v2` 标识，与产品基线 V1.0 不一致；这是已知文档/展示口径问题。

## 仅属规划，尚未实现

- Reminder Lifecycle 的细化状态机、Delivery 与 Attempt 实体。
- Memory Evolution：`memory_type`、`importance`、`entities`、`related_ids`、关联发现与主题聚合。
- Weekly Review、主动回顾、语义召回、向量检索。
- 多平台通知生态及 Simple Mode、Personal Mode、Setup Wizard。
- SQLite 主存储与正式 JSON→SQLite 迁移工具。
