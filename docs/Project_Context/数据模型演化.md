# 数据模型演化

## 当前：V1.0 JSON

- `recall.json`：当前 Recall Records 的唯一事实来源，Schema 1.01。
- `recall_history.json`：创建、更新、完成、删除和提醒等操作历史；不是当前状态事实来源。
- `config.json`：当前 webhook 备用配置。
- Markdown View：从 JSON 单向生成的派生阅读数据。

当前 Record 保留 `content`、分类、标签、提醒相关字段、状态、优先级、时间、来源和 `metadata`。旧 Markdown 可以迁移，Schema 可升级；迁移前要求备份并保持原文不丢失。

## 未来：Timeline 与 Event

既有目标将当前 Record 与其生命周期、History 进一步发展为能够表达时间演化的 Timeline / Event 模型。当前 History 只承担审计留痕，并不是完整事件溯源；Timeline、独立 Event Contract 尚未实现。

## 未来：Parent / Child Recall 与关联

既有 Memory Evolution 方向包括 `memory_type`、`importance`、`entities`、`related_ids`、主题聚合和关联记录。Parent / Child Recall 是未来可表达关系的一种方向，不是 V1.0 当前字段或行为。

## 未来：Reminder、Delivery、Attempt

目标数据模型会将提醒本体、每个渠道投递和每次投递尝试分开，以免把平台细节和多个状态持续塞入单一 Record。实施前仍需冻结 Contract 并验证兼容与迁移。

## 未来：SQLite 迁移

SQLite 是条件性方向，而非预定重构。复审信号包括真实性能问题、整体文件写入可靠性、原子多实体更新、并发、多用户/多实例、复杂关系查询或稳定的语义检索需要。迁移必须具备备份、验证、rollback、数据计数对账与保留 JSON/Markdown 可读性的方案；避免长期双写和双事实来源。

## 未来：Vector Memory

向量索引仅可作为可重建的派生索引，不能取代结构化主数据。是否引入须以真实评测、隐私和重建策略明确为前提。
